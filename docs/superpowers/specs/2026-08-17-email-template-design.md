# Pet Fly Inc Email Template Design

## Purpose

Create a consistent, professionally branded transactional email system for Pet Fly Inc. The first release uses fixed application-owned templates and gives administrators preview and test-send controls. It does not expose free-form template editing.

## Current Email Events

The system sends messages for quote submissions, contact submissions, PetConnect registration and verification resend, microchip finder messages, lost/found alerts, partner self-registration and claim resend, administrator partner invitations, signed contracts with PDF attachments, client portal account creation or password reset, and SMTP delivery tests.

Each event keeps its existing business behavior and recipient rules. The change is to centralize presentation, add plain-text alternatives, and make delivery behavior observable in the Admin Email Center.

## Brand And Layout

Templates use the existing PetFly visual language: a warm cream outer background (`#f7f5f0`), charcoal text (`#1a1a1a`), terracotta accent (`#c4622d`), a serif display heading with email-safe fallbacks, and a restrained sans-serif body font. The supplied `AROUNDLOGO.png` is copied to a deployment-safe public asset path and shown at a constrained width in the header with useful alternative text. The email remains understandable when images are blocked.

The shared table-based layout contains:

1. Brand header with logo and Pet Fly Inc name.
2. Heading and personalized greeting.
3. Event-specific content and optional detail panel.
4. One primary terracotta CTA, when action is required.
5. Plain-text URL below the CTA for clients whose email client blocks buttons.
6. Delivery guidance when an email contains a link, attachment, or password.
7. Support/footer information and current copyright year.

Markup will use conservative inline CSS and responsive width rules for Gmail, Outlook, Apple Mail, and mobile clients. Every HTML template has a plain-text equivalent.

## Template Catalog

### Action and security

- PetConnect email verification and resend
- Partner profile claim and claim resend
- Partner invitation
- Client portal access and temporary-password reset

These templates contain one clear action, explain the purpose and any expiry, and keep security-sensitive values system-controlled.

### Customer confirmations

- Quote request received
- Contact message received
- Signed contract confirmation with contract number and generated PDF attachment

These templates lead with confirmation, show the next expected step, and include spam-folder guidance.

### PetConnect communication

- Microchip finder message
- Lost/found pet alert

These templates show only the permitted pet and message details, preserve owner privacy, and use a focused portal/action link.

### Internal operations

- New quote notification
- New contact notification
- SMTP delivery test

Internal messages use the same brand shell but a denser operational detail layout and do not include customer spam guidance.

## Application Components

### Shared template module

Add a module such as `lib/email-templates.js` that owns the shared shell, reusable primitives (heading, button, detail rows, notice, footer), HTML escaping, and event-specific render functions. Each render function returns `{ html, text }` and accepts only the data needed for its event.

### Email delivery wrapper

Extend the existing SMTP wrapper to accept `{ to, subject, html, text, attachments, category }`. Preserve the current sender configuration and return a structured success/failure result. Do not place credentials, tokens, or local file paths in templates or source control.

### Admin Email Center

Add an admin page/section that lists the fixed templates, renders a sample preview, and sends a selected template to an explicitly entered test address. Display SMTP configuration health and the last delivery error. Test sends must use sample data and must not trigger real customer actions or expose production passwords.

## Spam-Folder Guidance

After successful quote, contact, and registration submissions, the website success state displays:

> We sent a confirmation email to your email address. Please check your inbox and spam or junk folder. Add `info@petflyinc.com` to your contacts to receive future updates.

Action emails repeat a shorter version inside the email. Internal staff messages do not.

## Data And Security Rules

- Verification, claim, portal, and reset URLs are generated by the server and cannot be edited in Admin.
- Temporary passwords, contract facts, PDF attachments, pet details, and recipient addresses are injected at send time.
- User-provided values are HTML-escaped before insertion.
- Owner contact details remain private in microchip workflows.
- Production links use the configured public site URL; localhost must never appear in outgoing mail.
- All templates include a plain-text fallback.

## Error Handling And Observability

Template rendering failures prevent sending and are logged with the event category. SMTP failures return a clear failure result, preserve the existing health endpoint behavior, and are visible in the Admin Email Center. The application should not report a successful customer submission when the database write failed. Where business behavior currently treats email delivery as best effort, that behavior remains unchanged and the response can expose a non-blocking delivery warning.

## Verification Plan

- Unit-test every renderer for required headings, recipient-safe content, CTA URLs, HTML escaping, and plain-text output.
- Verify every action template uses the public production URL and never localhost.
- Verify contract emails preserve the PDF attachment and contract number.
- Test previews and test sends from Admin with SMTP configured and misconfigured.
- Test blocked-image fallback text and mobile widths using representative email HTML snapshots.
- Regression-test quote, contact, registration, partner invitation, PetConnect messaging, alert, contract, and portal flows.

## Deliberate Scope Exclusions

The first release does not include arbitrary in-admin editing, marketing campaigns, unsubscribe management, email analytics, or a third-party email provider. Those can be evaluated after the fixed templates and delivery observability are stable.
